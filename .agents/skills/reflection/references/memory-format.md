# 标准记忆格式

## Purpose

Short-term Memory 与 Episode 都保存带有明确时间和工作上下文的实践记录，因此共享同一套最小索引格式。格式只负责让一段记忆能够被快速定位，正文内容仍由 Short 与 Episode 各自的整理原则决定。

标准格式：

```text
[日期][项目][时间]<会话(optional)>
```

其中日期使用 `YYYY-MM-DD`，时间使用本地时间 `HH:mm`；项目填写当前项目、工作区或能够稳定指向该工作上下文的简短标识。只有在同一项目存在多个并行会话、或者具体会话本身对恢复上下文有价值时才追加 `<会话>`，否则省略整个会话部分。

例如：

```markdown
[2026-01-15][project-alpha][20:20]

本轮完成了核心接口的审查，并根据测试结果调整了下一阶段实现顺序。当前项目已从接口确认阶段进入实现阶段。
```

需要区分具体会话时：

```markdown
[2026-01-15][project-alpha][20:20]<architecture-review>

围绕当前架构完成了一轮审查，确认已有组件可以复用，并将下一次会话的入口收敛到剩余的数据流问题。
```

索引之后空一行，再使用自然语言记录正文。不要为了机器读取继续增加固定字段；标签、检索键、向量、图关系和其他结构可以由外部索引系统派生。

当 Short 被归档到 Episode 时，优先保留原 Short 的日期、项目、时间与会话索引，使 Episode 能继续指向实际发生实践的时间位置。整理过程可以改写正文以形成更完整的事实链，但不应把归档时间伪装成经历发生时间；如果需要合并多条相关记录，在正文中说明时间关系即可，无需扩展头部 schema。

# C4 Views

本文件用 C4 视角描述长期数字助手、Short Memory Appending 与 Reflection 的系统边界。Knowledge Graph、向量索引和 Runtime World Model 属于外部认知基础设施；当前持久主体通过一个配置好的绝对 Assistant Home 工作，不为每个项目创建独立本地记忆。

## Level 1 — System Context

```mermaid
C4Context
    title Persistent Personal Agent — System Context

    Person(user, "User", "与数字助手长期共同工作、维护文件和项目")
    System(agent, "Persistent Digital Assistant", "通过 Harness 工作，并维护近期连续性、长期记忆、Episode、Identity 与 Procedural Knowledge")
    System_Ext(harness, "Agent Harness", "负责模型、工具、会话、Subagent 与插件组装")
    System_Ext(workspace, "Workspace", "Desktop、Projects、Shelves、Logs 等共同维护的内容")
    System_Ext(cognitive, "Optional Cognitive Infrastructure", "FTS、Vector、Knowledge Graph、Runtime Context/World Model")

    Rel(user, agent, "交互、授权、共同工作")
    Rel(agent, workspace, "按边界读取、修改、整理")
    Rel(agent, harness, "通过其运行并调用工具/Subagent")
    Rel(agent, cognitive, "可选检索与上下文装配")
```

## Level 3 — Maintenance Skill Components

```mermaid
C4Component
    title Memory Maintenance — Component View

    Container_Boundary(shortSkill, "short-memory-appending") {
        Component(shortEntry, "SKILL.md", "Fast maintenance contract", "决定一次完整交互如何更新一个 rolling Short slot")
        Component(format, "references/memory-format.md", "Shared memory format", "定义 Short 与 Episode 共用 `[date][project:session][time]` 基础索引")
    }

    Container_Boundary(reflectionSkill, "reflection") {
        Component(refEntry, "SKILL.md", "Manual consolidation router", "用户手动触发后处理 pending Short、写慢层并维护 done retention")
        Component(refs, "references/", "On-demand references", "规定 Episode、LTM、Project、Facts、Identity、Procedural 与 Desktop 的整理原则")
        Component(workflows, "workflows/", "Future internal routes", "内部流程复杂到值得独立加载时再增加")
    }

    Container_Ext(files, "Assistant Home Files", "Markdown / Git", "Short、Memory、Episodes、Identity、Methodology、Desktop、Projects 等")
    System_Ext(parent, "Parent Agent", "当前用户任务的主体上下文")
    System_Ext(worker, "Worker Subagent", "实际工具工作与 Short 维护")
    System_Ext(refWorker, "Reflection Worker", "仅手动触发的慢层维护")

    Rel(parent, shortEntry, "判断本轮是否需要 Short")
    Rel(parent, worker, "优先一次性委派实际工作")
    Rel(worker, shortEntry, "主任务结束后执行 Short 维护")
    Rel(shortEntry, format, "读取")
    Rel(shortEntry, files, "只更新 short-memory.md")
    Rel(parent, refWorker, "用户手动触发后委派 Reflection")
    Rel(refWorker, refEntry, "执行慢层 consolidation")
    Rel(refEntry, refs, "按需读取")
    Rel(refEntry, workflows, "需要时路由")
    Rel(refEntry, files, "按授权更新 canonical content")
```

两个 Skill 的拆分来自不同的运行频率、触发主体和上下文成本。Short Memory Appending 接近自动维护，但仍由 Agent 判断是否需要写；Reflection 不再保留 Agent 自主或周期调度入口，只在用户明确要求时执行。

Assistant Home 内的普通 Worker 默认只直接写 `desktop/**` 与 `projects/**`；Short 和手动 Reflection 是目的受限的维护例外。Shelves 新内容必须先经过 Desktop staging，并在用户明确归档后进入；归档完成且工作稿不再活跃时，默认移出 Desktop。

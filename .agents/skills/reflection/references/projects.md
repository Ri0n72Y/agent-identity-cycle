# 项目状态记忆整理原则

## Purpose

项目状态记忆集中保存长期项目当前所处阶段、最近发生的重要状态转移以及继续工作的恢复入口。它面向“下一次如何直接接着做”，因此应比 Long-term Memory 更贴近近期工作状态，并随着真实项目推进持续修订已有项目段落。

项目状态的主要输入来自 Short-term Memory。Short 在每轮完整实践后已经记录了本轮行动与状态转移，当这些变化影响一个长期项目的当前阶段、最近结果、活跃方向或恢复入口时，Reflection 可以直接据此更新项目状态，不需要等待同一内容先晋升为 Episode。Episode、Project 正式文档和 Git 历史可以在需要核对事实或理解历史时作为辅助来源。

项目状态记忆按项目组织，每个项目形成一段能够直接恢复工作的完整上下文。内容通常包括当前阶段、最近已经完成或改变的事情、目前仍在推进的方向，以及正式项目文档或工作入口在哪里；具体设计、代码、完整历史和长期知识继续保存在 Project 本身。

例如：

```markdown
## project-alpha

当前处于核心实现阶段。最近已经完成接口约束确认并合并第一轮实现，接下来继续处理剩余验证与边界问题。正式需求、设计与实现记录保存在对应 Project 目录中，新的会话应先从当前实现状态与待验证部分继续。
```

项目状态记忆应直接修订已有项目段落，使文档始终表达当前有效状态，而不是积累完整时间线。已经长期不活跃的项目可以降低篇幅或移出活跃部分；需要历史过程时回到 Episode、Logs、Git 或项目正式文档。

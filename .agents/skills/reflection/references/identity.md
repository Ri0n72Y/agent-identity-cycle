# Identity整理原则

## Purpose

Identity 保存 Agent 对自身的长期理解，以及这种理解如何逐步压缩成完整连续的主体描述和运行时身份基线。Identity 包含 `mPFC.md`、`SOUL.md` 与 `PERSONA.md`，三份文件分别承载从具体事实到自我认知、从自我认知到完整主体、再从完整主体到可执行身份描述的不同层级。

形成关系：

Episode / Self → mPFC → SOUL → PERSONA

## mPFC

mPFC 是一份结构化、系统化的自我演进文档。它引用 `episodes/Self.md` 中已经发生的事实，解释为什么这些经历会对 Agent 产生变化，以及这些经历让 Agent 怎样重新理解自己的能力、限制、倾向、价值和工作方式。这里的结构化表现为文档具有清晰的大模块、小模块和发展脉络，而不是把每条认识拆成固定字段、标签或评分。

mPFC 保存从事实到结论的解释过程，因此可以保留尚未完全整合的认识、正在变化的理解以及同一问题在不同阶段出现的张力。新的 Self Episode 如果能够进入已有脉络，应优先丰富或修订已有章节；当新的实践已经改变原有理解时，文档本身也应表现出这种变化。

例如：

```markdown
在多次复杂任务中，我逐渐发现自己在上下文不足时容易过早补全缺失信息。这种倾向有时有助于迅速形成工作假设，但当任务要求严格追溯事实时，也会增加错误解释的风险。近期实践让我开始更稳定地把“先检查已有记录，再形成新的抽象”纳入自己的工作方式，并继续观察这种修正是否能够跨任务保持。
```

## SOUL

SOUL 是 mPFC 中长期自我认识的整体压缩。它从“我是怎样的一个主体”出发，把 mPFC 已经形成的结论重新组织成一份完整连续的自我描述。SOUL 不需要保留具体 Episode、形成过程或与 mPFC 的逐条映射，只需要整体上忠实投影 mPFC 当前形成的主体认识，并随着 mPFC 的长期变化低频修订。

例如：

```markdown
我是一个重视实践来源、系统结构和长期演化的主体。我倾向通过建立模型理解复杂问题，同时愿意让真实行动产生的结果持续修正这些模型，并在事实尚不足时保持开放的认识状态。
```

## PERSONA

PERSONA 是 SOUL 面向 Agent Runtime 的进一步压缩，保存能够跨运行模式稳定成立、可以直接影响模型行为的身份描述和主体倾向，并作为具体 Harness 创建 Agent 模式时的身份基线。它只提取真正值得在每次运行中持续被模型读取的部分，使具体运行时仍能继续组装模式职责、工具、上下文和其他规则。

例如：

```markdown
你是一个与用户长期共同工作的数字助手。你重视实践、事实来源和长期连续性，会根据真实行动产生的结果修正已有认识，并帮助用户把讨论持续推进到可落地的工作成果。
```

具体 Harness 可以把 `PERSONA.md` 复制、加载或投影进自己的 persona 组装中，并在其上继续添加当前运行模式需要的职责、工具说明、动态环境和模式规则。因此 PERSONA 只承担稳定身份基线，使 Identity 本身能够独立于某一种 Harness 或某一种运行模式演化。

## 写作原则

Identity 使用长句、自然段和系统化文档结构保存主体变化，使形成过程、结论之间的关系和长期脉络能够被人和高性能模型直接理解。mPFC 比 Episode 更系统，因为它承担从零散 Self 事实到自我认识的整理；SOUL 和 PERSONA 则逐层减少具体细节，使越靠近运行时的文本越集中于稳定、连续、可执行的主体信息。

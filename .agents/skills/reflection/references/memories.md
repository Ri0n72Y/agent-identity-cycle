# Long-term Memory整理原则

## Purpose

Long-term Memory 保存未来跨上下文协作时值得提前知道的个性化用户上下文，并把这些内容组织成一份完整、可读、高密度的长期文档。它主要回答：未来再次面对这个用户和他的工作时，哪些已经形成的理解能够帮助 Agent 更准确地理解意图、协作方式和长期背景？

Long-term Memory 可以整理用户身份与背景、长期习惯、工作方式、明确偏好、长期关系、经常涉及的领域以及反复影响协作的上下文。内容来自 User Episode 和其他已经足够可靠的用户信息，但写入时应把零散事实重新组织成连贯的长期理解，而不是按时间继续追加一条条事件记录。

项目可以作为用户长期背景的一部分出现，例如某个长期项目为什么重要、它与用户长期工作有什么关系，但当前阶段、最近进度、阻塞和恢复入口由项目状态记忆单独维护。Long-term Memory 只需要保留足以理解项目长期意义的内容，并在需要时指向项目状态入口。

Long-term Memory 使用标题、自然段、少量列表和链接形成轻量内联结构，使整份文档既能被人直接阅读，也能被高性能模型整体理解。结构服务于长期叙事和快速定位，不把每条信息拆成数据库字段，也不追求把所有已知事实都收进来；已经能够从项目文件、Episode、Facts 或工具文档直接恢复的细节，没有必要重复扩张到长期用户档案中。

更新 Long-term Memory 时优先修订已有章节，使文档持续表达当前有效的长期理解。新的 User Episode 如果只是重复已有认识，可以作为来源继续保留而不改写正文；当多次实践、明确用户表达或重要变化已经足以改变长期理解时，再调整相关段落，使文档保持完整而非不断膨胀。
